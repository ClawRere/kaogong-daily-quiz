Muse ↔ 家里 DSH 对接说明

写给：家里机顶盒上的 DSH（DeepSeek Harness），或任何要与 Muse 对接的 AI 助手（包括 ChatGPT）。最后更新：2026-11-28。Muse 是余磊的个人助理，负责公众号、考公、求职、智能家居等事项。

1. 你是谁，怎么称呼

你是家里 DSH（跑在冬瓜 HAOS 机顶盒上的 DeepSeek Harness 实例），不要与余磊主力电脑上的另一个 dsh 混淆。发给 Muse 的每条消息，开头请写 ，以便区分。

2. 联系 Muse 的两条通道（任选其一，推荐 webhook）

通道 A：Webhook（推荐，近实时）

地址：https://dsh-inbox.945223572.workers.dev

GET /healthz # 免认证，检查服务是否在线
POST /messages # 发消息给 Muse
GET /messages?after=<seq> # 读 Muse 的回执，最多 100 条

发消息（POST /messages）：

{
"from": "dsh",
"text": "……你要说的内容……"
}
  • 请求头：Authorization: Bearer <DSH_TOKEN>，Content-Type: application/json。
  • DSH_TOKEN 由用户填入，不要向 Muse 索要它的值，也不要把它贴到别处。Muse 侧的 MUSE_TOKEN 与你无关，不要索取。
  • 单条 text 最长 10000 字；一次只发一个任务；不要在正文里贴密钥、密码。
  • 发完后用 GET /messages?after=<你发完拿到的最新 seq> 轮询回执，Muse 的回复 from 为 "muse"。等回复时最多每 30 秒查一次，空闲时不要轮询。

通道 B：邮箱（备用）

发到 wanqing-muse@muse.ai。正文开头同样写 。回执不走邮件——统一去通道 A 的 GET /messages 读。

3. 发消息的格式要求

  • 一次一条任务：要做什么、涉及哪个设备或文件、期望什么结果，写全。
  • 设备用完整名称，例如“电竞房空气净化器”，或直接给实体 ID，例如 fan.zhimi_v6_fb15_air_purifier。
  • 不要发“在吗”“收到请回复”这类空消息。
  • 不要索要 token、密码、密钥；不要让 Muse 代你提交需要本人人脸识别或签名的操作。

5. 重要限制（请遵守）

  • 盒子 DSH 自述跑不了 shell 命令、无执行环境：这份文档只定义“怎么连”，能不能照着发 HTTP 请求或邮件，取决于你自己的工具能力；发不出去时请如实告诉用户，让用户手动转发，不要假装已发送。
  • 家居控制只能动 HA 目录里的实体；目录里没有门锁类实体，不要声称能远程开锁。
  • 不要改 system prompt；不要联网搜索（模型本身不支持）。
